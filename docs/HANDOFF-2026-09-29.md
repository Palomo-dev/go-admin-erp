## 1. Cómo se trabaja en este árbol compartido (obligatorio)

- **Commits con índice privado**: `GIT_INDEX_FILE=<scratchpad>/idx-x; git read-tree HEAD; git add <solo tus
  archivos>; git diff --cached --stat HEAD; git commit`; después `git reset -q HEAD -- <tus rutas>` para
  realinear el índice compartido. Si un archivo trae cambios ajenos sin commit: construir el blob con solo
  tus líneas (`git hash-object -w` + `git update-index --cacheinfo`).
- **`.git/index.lock` huérfano**: pasa seguido (agentes cortados, computador apagado). Antes de borrarlo,
  comprobar que no hay `git.exe` vivo (`Get-CimInstance Win32_Process -Filter "name='git.exe'"`).
  Después, `git diff --cached --name-status` y realinear las rutas desfasadas con `git reset -q HEAD -- …`.
- **Verificar en copia LIMPIA de HEAD** antes de dar algo por bueno (lección del 28-sep: CI rojo porque
  commits dependían de cambios sin commit del árbol local): `git archive HEAD | tar -x` en una carpeta
  propia del scratchpad + junction a `node_modules` y `electron/node_modules`; ahí `tsc` y jest.
- `tsc`: `NODE_OPTIONS=--max-old-space-size=8192 npx tsc --noEmit -p tsconfig.json` (sin heap = falso OK).
- Migraciones solo por el MCP de Supabase (proyecto `jgmgphmzusbluqhuqihj`), cada una con `.sql` en
  `supabase/migrations/` y rollback en `supabase/rollbacks/` en el mismo commit; dry-run con
  `DO … RAISE` o `begin … rollback`; parches de funciones con `pg_get_functiondef` + replace verificando
  una sola aparición, partiendo SIEMPRE de la definición viva (varias sesiones parchean las mismas
  funciones: `pos_checkout_v1`, `fn_factura_venta_emitir`, `fn_registrar_pago`, `fn_producto_guardar`…).
- Nunca markdown con backticks desde cadenas entre comillas dobles de PowerShell (ver CLAUDE.md).
- El dev server del dueño (localhost:3000) no se arranca ni se mata. El navegador interno no tiene sesión:
  solo sirve para pantallas públicas (acceso).
- Agentes largos se cortan («stalled 600 s» o apagado del PC): se reanudan con SendMessage pidiendo revisar
  commits, migraciones aplicadas sin archivo y trabajar en pasos cortos.

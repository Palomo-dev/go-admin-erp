# F-04 — Número de factura no único

**Severidad:** Bloqueante
**Estado:** Documentado
**Fase:** Fase 3a

## Qué es

No existe restricción de unicidad sobre `(organization_id, number)` en
`invoice_sales`. En producción hay 6 duplicados reales.

## Evidencia

### Duplicados en producción

| Org | Número | Repeticiones |
|---|---|---|
| 134 | FACT-0039 | 4 |
| 134 | FACT-0041 | 2 |
| 134 | FACT-0042 | 2 |
| 134 | FACT-0043 | 2 |
| 115 | FACT-25357 | 2 |
| 2 | NC-0001 | 2 |

### Causa raíz

`cotizacionesService.ts:66-90` (`generateQuotationNumber`) y
copiado de nuevo en `:349-362` dentro de `convertToInvoice`:
```ts
const { data } = await supabase.from('invoice_sales')
  .select('number').order('created_at', { ascending: false })
  .limit(1);
const nextNumber = (parseInt(data[0].number.match(/FACT-(\d+)/)) || 0) + 1;
```

SELECT + parseInt + 1 desde el navegador. Dos usuarios simultáneos
leen el mismo último número.

### Agravante

Org 115 tiene 183 números con formato irregular (`'Fac 1571 hs'`,
`'LAR-6921 DE'`) que el regex `/FACT-(\d+)/` no matchea. `nextNumber`
cae a 1 → colisión garantizada.

## Arreglo

1. **RPC `fn_next_invoice_number`** que consuma `invoice_sequences`
   con `UPDATE ... RETURNING` (atómico). Usada por POS, facturas y
   cotizaciones.
2. **Índice único parcial** sobre `(organization_id, number)`
   `WHERE status <> 'void'`.
3. Migrar `generateQuotationNumber` y `convertToInvoice` a usar la
   RPC.

## Qué falta

4. Guardrails.test.ts: verificar que dos inserts simultáneos no

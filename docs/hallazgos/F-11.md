# F-11 — Funciones SECURITY DEFINER expuestas a anon

**Severidad:** Alta
**Estado:** Parcial (103 triggers revocados; 216 → 184 tras la migración B de F0-SEC, 2026-09-16)
**Fase:** Fase 1

## Qué es

326 funciones `SECURITY DEFINER` estaban expuestas a `anon` vía
`/rest/v1/rpc/`. Cualquiera podía llamarlas sin autenticación.

## Acción tomada

- 103 funciones de trigger revocadas (`REVOKE FROM PUBLIC`). Ninguna se
  llama como RPC desde el cliente (verificado con grep).
- Resultado: 326 → 223 funciones expuestas a anon (-103).
- Migración: `supabase/migrations/20260910170000_f11_revoke_trigger_functions_from_public.sql`

## Qué falta

- 223 funciones no-trigger siguen expuestas. Necesitan análisis
  individual: agregar validación interna de `organization_id` antes de
  revocar. Fase 2.
- Ver F-11b: 433 funciones tienen `search_path` mutable.

## Actualización 2026-09-16 (F0-SEC A+B, qa r3 / builder r4)

- Migración B `20260915223000_crm_v4_f00_40_cerrar_rpc_crm_anon` **aplicada**:
  las `fn_reporte_crm_*` ya no son ejecutables por `anon` y llevan guarda de
  pertenencia (`ORG_FORBIDDEN`). Conteo verificado por el QA r3 con un `SELECT`
  por el MCP: funciones `SECURITY DEFINER` ejecutables por `anon` **216 → 184**.
- Consumidor corregido antes de aplicarla: el asistente de reportes
  (`src/app/api/ai-assistant/reportes/route.ts`) ejecuta las RPC con el cliente
  de sesión (`ctx.supabase`), nunca con el cliente browser (`anon` en servidor).
- `fn_rate_limit_hit` + `rate_limit_buckets` (F0-SEC C+D) **existen** en
  producción. Pendiente fuera del código: `RATE_LIMIT_STORE=db` en Vercel para
  que el rate limit deje de ser por instancia.
- Quedan 184 funciones no-trigger expuestas a `anon`: siguen necesitando
  análisis individual (guarda de `organization_id` y luego `REVOKE`).

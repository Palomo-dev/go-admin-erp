# F-14 — 86 políticas re-evalúan auth.uid() por fila

**Severidad:** Media (rendimiento)
**Estado:** Documentado
**Fase:** Fase 3b

## Qué es

86 políticas RLS usan el patrón `organization_id IN (SELECT ...
WHERE user_id = auth.uid())` que llama a `auth.uid()` una vez por
fila examinada. Además 194 avisos de `multiple_permissive_policies`.

## Evidencia

### auth.uid() por fila

```sql
-- Patrón lento (86 políticas):
organization_id IN (
  SELECT organization_id FROM organization_members
  WHERE user_id = auth.uid() AND is_active = true
)
```

`auth.uid()` se evalúa una vez por fila examinada. Envolverlo en
`(SELECT auth.uid())` lo convierte en InitPlan evaluado una vez:

```sql
-- Patrón rápido:
organization_id IN (
  SELECT organization_id FROM organization_members
  WHERE user_id = (SELECT auth.uid()) AND is_active = true
)
```

Cambio puramente sintáctico — mismo resultado, mejor plan.

### multiple_permissive_policies

194 avisos: el patrón `*_select_policy` + `*_insert_update_delete_policy`
con `FOR ALL` hace que cada SELECT evalúe dos políticas con la misma
condición. Fusionar en una sola política `FOR ALL` elimina la
duplicación.

## Arreglo

1. Envolver `auth.uid()` en `(SELECT auth.uid())` en 86 políticas.
2. Fusionar políticas `FOR ALL` duplicadas.
3. Aplicar vía MCP.

## Qué falta

No bloquea lanzamiento. Hoy no duelen porque no hay volumen. Con
clientes reales, 86 políticas evaluando `auth.uid()` por fila se
note en cada query.

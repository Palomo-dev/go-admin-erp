# F-17 — Mismo patrón de escrituras sueltas en 3 servicios más

**Severidad:** Crítica
**Estado:** Documentado
**Fase:** Fase 3a

## Qué es

El mismo patrón de F-16 (múltiples escrituras sueltas desde el cliente
sin transacción) aparece en transferencias, cotizaciones y notas
crédito.

## Evidencia

| Servicio | Archivo:Líneas | Escrituras sueltas |
|---|---|---|
| Transferencias | `transferenciasService.ts:171-234` | INSERT transfer + UPDATE cuentas + INSERT asiento |
| Cotizaciones | `cotizacionesService.ts:337-428` | INSERT cotización + INSERT items + UPDATE estado |
| Notas crédito | `notasCreditoService.ts:269-317` | INSERT nota + UPDATE factura + INSERT asiento reverso |

Cada uno hace N llamadas independientes a Supabase desde el cliente.
Si cualquiera falla a mitad de camino, los datos quedan inconsistentes.

## Causa raíz

Misma que F-16: lógica de negocio multi-tabla en el cliente en vez de
RPC transaccional.

## Arreglo

Mover cada uno a una RPC transaccional. Mismo patrón que F-16.

## Relación con F-32

F-32 se absorbe aquí: cuando la creación de factura pase a RPC
transaccional (parte del mismo esfuerzo que F-16/F-17), la race
condition que genera asientos inconsistentes desaparece.

## Qué falta

1. Crear RPCs transaccionales para cada servicio.
2. Reemplazar las llamadas sueltas.
3. Guardrails.test.ts: verificar atomicidad en cada uno.

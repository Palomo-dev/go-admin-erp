# F-20 — Errores convertidos en ceros

**Severidad:** Media
**Estado:** Documentado
**Fase:** Fase 3b

## Qué es

6 métodos de `reportesFinancierosService` atrapan errores de Supabase
y retornan 0 en vez de propagar el error. El reporte muestra "sin
movimientos" cuando en realidad fue un error de consulta.

## Evidencia

`reportesFinancierosService.ts`: 6 métodos con el patrón:
```ts
const { data, error } = await supabase.from(...).select(...);
if (error) return 0; // ← error silenciado
return data.reduce(...);
```

El usuario ve un reporte en ceros sin saber que hubo un error.

## Causa raíz

Prototipado rápido: retornar 0 es más fácil que manejar el error. Pero
silencia fallos de RLS, de conexión, de permisos.

## Arreglo

Propagar el error. El reporte debe mostrar "Error al consultar" o
"Sin datos", no un falso cero.

## Qué falta

1. Identificar los 6 métodos.
2. Reemplazar `return 0` por throw o estado de error.
3. Guardrails.test.ts: verificar que un error de consulta no produce
   un falso cero.

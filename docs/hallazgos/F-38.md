# F-38 — La carga masiva de inventario no deja rastro

**Severidad:** Bloqueante (lanzamiento)
**Estado:** Documentado
**Fase:** Fase 2

## Qué es

`src/app/app/inventario/productos/importar/page.tsx:1351-1359` inserta en
`stock_levels` y NO crea `stock_movements`. El inventario cargado por CSV
no tiene historia.

## Evidencia

### Hueco de kardex

De 31.148 filas en `stock_levels`, 28.949 con stock positivo (93%) no
tienen ningún `stock_movements` que las explique. Por organización:

| Org | Filas con stock | Sin movimiento |
|---|---|---|
| 137 | 16.407 | 16.406 |
| 135 | 6.088 | 5.779 |
| 132 | 2.748 | 2.401 |
| 139 | 1.697 | 1.697 |
| 134 | 891 | 864 |
| 128 | 688 | 688 |
| 144 | 411 | 411 |
| 138 | 214 | 214 |
| 125 | 201 | 201 |
| 120 | 198 | 165 |
| ... | ... | ... |

El 93% del inventario no tiene kardex. Esto no es un caso edge — es la
regla.

### Consecuencias, en orden de gravedad

1. **Sin stock_movements no hay kardex.** Ese inventario no tiene
   historia: nunca "entró" a ningún libro auxiliar. Un conteo físico
   muestra producto, el kardex muestra que nunca llegó nada.
2. **Sin movimiento no hay trigger**, así que tampoco hay asiento. F-36
   es consecuencia de esto, no un problema paralelo.
3. **Sin rastro no hay auditoría:** nadie puede responder de dónde salió
   ese stock ni quién lo cargó.

### Por qué bloquea el lanzamiento

Es la ruta de onboarding. Todo cliente nuevo carga catálogo e inventario
por CSV antes que nada. Cada uno va a arrancar con un inventario sin
historia y sin contabilizar.

## Causa raíz

El import CSV inserta directamente en `stock_levels` sin crear el
`stock_movements` correspondiente. El trigger `trg_auto_journal_stock_movement`
escucha INSERT en `stock_movements`, no en `stock_levels` — nunca se
dispara.

## Arreglo

El import CSV debe crear `stock_movements` con `source='initial'` por
cada producto con stock inicial, y exigir costo cuando hay cantidad.

Orden correcto:
1. F-38 — el import CSV debe crear `stock_movements` con `source='initial'`
   por cada producto con stock inicial, y exigir costo cuando hay cantidad.
2. F-36 — validar costo en `NuevoProductoForm`,
   `FormularioEdicionProducto` y `adjustmentService`.
3. Después, el asiento de apertura.

## Relación con F-36

F-36 (stock sin costo) y F-38 (stock sin movimiento) son problemas
distintos pero se refuerzan: el import CSV no crea movimiento (F-38) Y no
valida costo (F-36). Arreglar F-38 sin validar costo crearía movimientos
con `unit_cost=0` que el trigger igualmente rechazaría. Ambos se
arreglan juntos en la misma ruta.

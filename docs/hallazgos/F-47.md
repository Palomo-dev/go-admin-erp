# F-47 · fn_create_journal_entry ejecutable por anon y authenticated

**Severidad:** Alta
**Estado:** Corregido (REVOKE aplicado)
**Bloque:** A (bloqueante de lanzamiento)

## Hallazgo

`fn_create_journal_entry` y `fn_create_journal_entry_with_discount` eran
ejecutables por `anon` y `authenticated`. Ambas son `SECURITY DEFINER`,
escriben asientos contables y reciben `organization_id` como parámetro.

Un usuario autenticado de cualquier organización podía llamar directamente:

```sql
SELECT fn_create_journal_entry(
  p_organization_id := <org ajena>,
  p_branch_id := 0,
  p_entry_date := now(),
  p_memo := 'fraude',
  p_source := 'manual',
  p_source_id := 'x',
  p_debit_account := '1105',
  p_credit_account := '4105',
  p_amount := 1000000
);
```

y crear un asiento en la organización que quisiera.

## Corrección aplicada

```sql
REVOKE ALL ON FUNCTION public.fn_create_journal_entry(...) FROM PUBLIC, anon, authenticated;
GRANT EXECUTE ON FUNCTION public.fn_create_journal_entry(...) TO service_role;

REVOKE ALL ON FUNCTION public.fn_create_journal_entry_with_discount(...) FROM PUBLIC, anon, authenticated;
GRANT EXECUTE ON FUNCTION public.fn_create_journal_entry_with_discount(...) TO service_role;
```

ACL verificado después del REVOKE:
```
{postgres=X/postgres, service_role=X/postgres}
```

Solo `postgres` y `service_role` tienen EXECUTE. Las 51 funciones
`fn_auto_journal_*` que la llaman son `SECURITY DEFINER` del owner, así que
siguen funcionando bajo triggers.

## Verificación de que la app no la llama directamente

```
grep -rn "fn_create_journal_entry" src/ --include=*.ts --include=*.tsx
```

Resultado: 0 coincidencias. La app no llama `fn_create_journal_entry`
directamente vía `supabase.rpc()`. Solo la llaman las funciones del servidor.

DEFINER expuestas), por encima de las otras 533.

# F-48 · Doble asiento POS: invoice_sales + sales

**Severidad:** Crítica
**Estado:** Corregido: un devengo por venta (2026-09-23); 2.310 duplicados neutralizados
**Bloque:** A (bloqueante de lanzamiento)

## Mecanismo

Es F-01 con otro par de triggers. Estuvo activo todo este tiempo; se hizo
visible porque F-42 puso IVA en las líneas.

```
trg_auto_journal_sale      INSERT en invoice_sales  → fn_auto_journal_sale
trg_auto_journal_sale_pos  INSERT/UPDATE en sales   → fn_auto_journal_sale_pos
```

Ambos con `tgenabled='O'`. Una venta POS inserta en las dos tablas
(`invoice_sales.sale_id` enlaza el par) y cada trigger emite un asiento
completo.

En `posService` el orden es: INSERT `sales` (línea 1368/1856) → INSERT
`invoice_sales` (línea 1414/2124). Por eso el asiento `sales` siempre existe
cuando corre el trigger de la factura.

## Evidencia — org 140, venta dd05a47b / FACT-0006, 27.000 con IVA incluido

```
asiento 12111 source=sales          1305 D 27.000 | 2405 C 4.310,93 | 4105 C 22.689,07
asiento 12112 source=invoice_sales  1105 D 27.000 | 2405 C 4.310,93 | 4105 C 22.689,07
```

Resultado: ingreso 45.378,14 en vez de 22.689,08; IVA 8.621,86 en vez de
4.310,93; activo 54.000 en vez de 27.000.

Las 40 ventas `paid` sin factura **dependen de `fn_auto_journal_sale_pos`**
para contabilizarse. Desactivar ese trigger sin más dejaría esas ventas sin
asiento. Las 65 `pending` no tienen asiento porque el trigger solo procesa
`paid/confirmed/completed` — correcto.

### Paso 2 — Asientos múltiples por UPDATE

```
total_asientos_sales: 2.152
ventas_distintas:     2.152
asientos_extra:       0
```

El UPDATE (pending → paid) **no** genera asientos adicionales: la
idempotencia por `source_id` de `fn_auto_journal_sale_pos` funciona. El
conteo de 2.042 duplicados es exacto, no es piso.

## Medición INSERT vs UPDATE (2026-09-21) — decide la ruta

Nota metodológica: la comparación contra `s.updated_at` no sirve — en todas
las filas medidas, `s.updated_at == s.created_at` (el UPDATE de pago no toca
`updated_at`). La medición válida compara `je.created_at` del asiento POS
contra `inv.created_at` de la factura:

| Métrica | Valor |
|---|---|
| Duplicadas medidas | 2.133 |
| Asiento sales nació ANTES de la factura (INSERT) | **2.085 (97,8%)** |
| Asiento sales nació DESPUÉS de la factura (UPDATE) | 48 (2,2%) |
| En el mismo instante (< 2 s) | 1.861 |

**El asiento POS nace en el INSERT, antes de la factura.** El flujo del POS
inserta la venta ya como `paid`; cuando corre el trigger, la factura no
existe todavía.

Consecuencia: el chequeo 1 de la propuesta original (POS se abstiene si
existe factura) no se activaría en el 97,8% de los casos. **No hay arreglo
pequeño: se requiere RPC transaccional** que inserte venta + factura y
contabilice una sola vez, con la factura como documento canónico.

## Propuesta original (DESCARTADA — ver medición INSERT vs UPDATE)

Conservar ambas rutas con verificación cruzada, no desactivar triggers:

1. En `fn_auto_journal_sale_pos`, antes de crear el asiento:
   ```sql
   -- F-48: si la venta tiene factura asociada, la factura es el documento contable
   IF EXISTS (SELECT 1 FROM invoice_sales inv WHERE inv.sale_id = NEW.id) THEN
       RETURN NEW;
   END IF;
   ```

2. En `fn_auto_journal_sale`, antes de crear el asiento:
   ```sql
   -- F-48: si la factura viene de una venta POS que ya tiene asiento, no duplicar
   IF NEW.sale_id IS NOT NULL AND EXISTS (
       SELECT 1 FROM journal_entries je
       WHERE je.source = 'sales' AND je.source_id = NEW.sale_id::text
   ) THEN
       RETURN NEW;
   END IF;
   ```

Cubre todos los escenarios sin importar el orden de inserción:

| Escenario | Resultado |
|---|---|
| Venta POS con factura (sales primero) | sale_pos crea; factura ve asiento de la venta y no crea. 1 asiento. |
| Venta pending → factura → pago después | factura crea; UPDATE a paid ve factura y no crea. 1 asiento. |
| Venta POS sin factura (40 paid) | sale_pos crea. Se contabiliza. |
| Venta pending sin factura → pagada | UPDATE a paid: no hay factura, crea. Se contabiliza. |
| Factura directa sin venta | fn_auto_journal_sale normal. |

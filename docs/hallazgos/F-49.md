# F-49 · Factura en draft con asiento posted

**Severidad:** Alta
**Estado:** Corregido: allow-list issued/paid/partial y disparo al emitir (2026-09-23)
**Bloque:** A (bloqueante de lanzamiento)

## Hallazgo

FACT-0005 (org 140) tiene `status='draft'` y su asiento 12110 tiene
`posted=true`. Un borrador no debería llegar al libro mayor.

## Causa

`fn_auto_journal_sale` no filtra por `status`, solo por `document_type`:

```sql
IF NEW.document_type IS NOT NULL AND NEW.document_type != 'invoice' THEN
    RETURN NEW;
END IF;
```

Cualquier INSERT en `invoice_sales` con `document_type='invoice'` (o NULL)
genera asiento, incluidos los borradores.

## Corrección propuesta (no aplicada)

Contabilizar SOLO cuando el estado es contabilizable — allow-list, no
block-list:

```sql
-- Contabilizar solo cuando status IN ('issued', 'paid')
IF NEW.status IS NULL OR NEW.status NOT IN ('issued', 'paid') THEN
    RETURN NEW;
END IF;
```

Nota: la redacción anterior de este archivo decía "filtrar
`status NOT IN ('issued','paid')`", que leído como criterio de contabilización
excluye justo las facturas que SÍ deben contabilizarse y deja pasar los
borradores. La regla correcta es allow-list: contabilizar solo
`('issued', 'paid')`, y todo lo demás (draft, void, ...) no contabiliza.

Verificar antes qué valores de `status` son contabilizables en producción
(draft, issued, paid, void...) y si el UPDATE a `issued` desde `draft`
dispara algún trigger que contabilice después.

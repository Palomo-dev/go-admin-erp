# F-50 · tax_code inconsistente entre rutas

**Severidad:** Media
**Estado:** Corregido: tax_code derivado en la base para toda ruta (2026-09-23)
**Bloque:** A (bloqueante de lanzamiento)

## Hallazgo

En la misma org, con 3 minutos de diferencia:

- FACT-0005: `invoice_items.tax_code = 'IVA_19'`
- FACT-0006: `invoice_items.tax_code = NULL`

Ambas con `tax_rate = 19`. El resolver puebla `tax_code` solo en algunas
rutas.

## Dónde se pierde

`resolveLineTax` devuelve `tax_code` del item (paso 1) o lo resuelve desde
`appliedTaxTotals` (paso 2) / `product_tax_relations` (paso 3) /
`organization_taxes` (paso 4). El caso FACT-0006 sugiere que la ruta POS o la
ruta de factura directa toma la tasa por un camino que no trae código
(por ejemplo, `itemTaxRate > 0` con `itemTaxCode` NULL: el paso 1 retorna el
código que trae el item, que puede ser NULL).

## Corrección propuesta (no aplicada)

1. En el paso 1 del resolver, si `itemTaxRate > 0` pero `itemTaxCode` es
   NULL, continuar a los pasos 2-4 solo para resolver el código (sin cambiar
   la tasa).
2. Alternativa: mapear tasa → código con la tabla `tax_templates` del país
   (COL): 19 → 'IVA_19', 5 → 'IVA_5', 0 → 'IVA_0'.
3. Cubrir con tests unitarios el caso `itemTaxRate=19, itemTaxCode=NULL`.

## Estado al 2026-09-23 (cierre del núcleo contable)

`fn_codigo_impuesto_linea` + disparador. 280 líneas históricas con tarifa 19
recibieron `IVA_19`; 7 con tarifas que no son ninguna tarifa quedaron en la
auditoría `invoice_item_tax_audit`. Tarifa 0 sin relación explícita queda en
NULL (no se afirma «exento»; ADR-CC-004).

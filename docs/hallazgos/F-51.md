# F-51 · Divergencia de redondeo de 1 centavo entre rutas

**Severidad:** Baja
**Estado:** Corregido: una sola regla de redondeo (2026-09-23)
**Bloque:** D (antes del cierre de mes)

## Hallazgo

Para el mismo bruto de 27.000 con IVA 19% incluido:

- Factura (FACT-0005/0006): `tax_total = 4.310,92`
- POS (sales): `tax_total = 4.310,93`

Un centavo de diferencia entre rutas para el mismo documento.

## Causa

Dos fórmulas distintas para separar base e impuesto:

- Trigger `fn_recalc_invoice_totals`:
  `base = (bruto - descuento) / (1 + r/100)`, `iva = bruto - base`
- POS (`posService`): cálculo propio con otro orden de redondeo.

## Regla única propuesta (no aplicada)

Calcular en un solo lugar del resolver:

```
base = round(bruto / (1 + r/100), 2)
impuesto = bruto - base
```

Derivar el impuesto por resta garantiza que `base + impuesto = bruto`
exactamente, eliminando la divergencia de 1 centavo entre rutas.

## Estado al 2026-09-23 (cierre del núcleo contable)

`base = round(bruto / (1 + tasa/100), 2)`, impuesto por resta, en
`fn_recalc_invoice_totals` y en `splitGrossLine` (taxResolver.ts), con tests
(27.000 al 19% → 22.689,08 + 4.310,92).
